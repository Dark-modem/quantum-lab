# quantum-lab — Phase 1C lab harness

Local test lab for the Quantum panel/agent stack. This repo owns **only the lab
tooling**: deploy scripts, smoke tests, the traffic-overhead measurement
harness, and failure-injection tests. It never edits the product repos
(`quantum-panel`, `quantum-agent`, `quantum-protocol`).

Branch: `phase1/lab`. Remote: private `Dark-modem/quantum-lab` (created because
`gh` was authenticated at phase start).

## Test topology

Two disposable Ubuntu test servers (root via SSH key auth only — no passwords):

| alias (in `~/.ssh/config`) | role | notes |
|---|---|---|
| `qlab-iran` | agent (mesh **node**) | 1 vCPU / 1 GB RAM |
| `qlab-germany` | panel + agent (mesh **hub**) | 2 vCPU / 4 GB RAM, reached via `ProxyJump qlab-iran` |

Aliases may be overridden with `QL_IRAN_HOST` / `QL_GERMANY_HOST` env vars.
The scripts never embed hostnames, IPs, or credentials; they only reference
SSH aliases resolved from `~/.ssh/config`.

## Layout

```
scripts/
  lib.sh               shared helpers (ssh batching, JSON, counters)
  capture-baseline.sh  OS-state snapshot per host (restore reference)
  deploy.sh            build + ship panel/agent, systemd units; --rollback --wipe
  smoke.sh             enroll, heartbeat, desired-state, panel-death test
  bench/overhead.sh    traffic-overhead harness (engine-agnostic)
  bench/engines/*.sh   one adapter file per tunnel engine (matrix.sh, none.sh)
  failtests.sh         engine-kill / netem loss / blackhole detection+recovery
docs/
  OVERHEAD-METHOD.md   how overhead is measured, in plain language
  RUNBOOK.md           how to reproduce every result
results/
  baseline/<host>/     pre-touch OS snapshots (committed: text only)
  overhead-<date>.md   measurement report + JSON
  failtests-<date>.md  failure-test report + JSON
```

## Rules of the lab

1. Nothing destructive happens anywhere except on the two test servers.
2. The two servers are wiped/disposable; still, we snapshot their pre-touch
   state and can restore sshd/ufw/sysctl from it (`scripts/restore-baseline.sh`).
3. No passwords are stored in this repo or in any log. The panel credential is
   generated by the panel binary itself (argon2id hash on disk, plaintext shown
   exactly once, in the phase report chat).
4. Every result file states what was actually run. Anything not executed is
   marked `UNVERIFIED`.
5. Scripts are committed; binaries are not (`out/` is gitignored).
